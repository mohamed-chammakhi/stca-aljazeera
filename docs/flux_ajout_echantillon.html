Simple project flow

How one collector sample travels through your project

This page follows one small action: the collector clicks Ajouter, fills the form, and the sample appears in the list. You do not need to understand every line of code. Follow the arrows and look only at the highlighted lines.

The easiest way to understand the architecture: the screen does not save directly to the database.
The screen asks a service. The service asks the API client. The API client talks to Django. Django saves in the database. Then the saved sample comes back to the screen.

4

The service prepares the data for Django

This is an important architecture rule in your project: the page does not talk to the server directly. The service is the middle person.

File to open

lib/2_collecteur/mes_echantillons/services/echantillon_collecteur_service.dart

Look at lines 95 to 108, then 161 to 173.

The important code

final response = await apiClient.post(
  '/api/echantillons/',
  _toDjangoMap(e),
);

return EchantillonCollecteur.fromJson(
  _toFlutterMap(response),
);
Before service Flutter object EchantillonCollecteur( referenceBouteille: "B-1207", variete: "Chemlali" )
Service prepares Django field names { "reference_bouteille": "B-1207", "variete": "Chemlali" }
Why? Flutter and Django do not name everything the same way. The service translates between both sides.
5

The API client sends the real HTTP request

The API client is the only class responsible for HTTP. It adds the login token, converts the Dart map into JSON text, sends the request, and reads the response.

File to open

lib/core/api_client.dart

Look at lines 225 to 235.

The important code

final headers = await _headers();

final response = await _send(
  () => http.post(
    _uri(path),
    headers: headers,
    body: jsonEncode(body),
  ),
);
The request looks like this: POST /api/echantillons/ with a JSON body and an Authorization: Bearer token header.
6

Django receives the sample and saves it

Django checks that the connected user is allowed to create samples. Then it validates the data and saves it. The collector is not typed by the user; Django knows the collector from the login token.

In simple words: "Only a collector can create this. The backend attaches the sample to the logged-in collector automatically."
7

The saved sample comes back with server values

Before saving, the sample has temporary local values. After saving, Django returns the official database version: real UUID, official number, date, collector id, and other fields.

Flutter sends No official id yet { "reference_bouteille": "B-1207", "variete": "Chemlali", "statut_collecteur": "receptionne" }
Django returns Saved record { "id": "uuid-from-database", "numero": "2026/0042", "reference_bouteille": "B-1207", "date_ajout": "2026-05-17T..." }
Service converts back JSON becomes a Dart object again. EchantillonCollecteur.fromJson( _toFlutterMap(response) )

The architecture in one sentence

For this feature, your project works like this:

Flutter page opens the form, the form creates a sample object, the service prepares it, ApiClient sends it to Django, Django validates and saves it, then the saved sample comes back and setState() updates the screen.

Files you should open, in this exact order

  1. lib/2_collecteur/mes_echantillons/mes_echantillons_page.dart - button, service call, screen update.
  2. lib/2_collecteur/mes_echantillons/widgets/dialogs/formulaire_dialog.dart - form fields become sample objects.
  3. lib/2_collecteur/mes_echantillons/services/echantillon_collecteur_service.dart - sample is prepared for Django.
  4. lib/core/api_client.dart - HTTP POST is sent.
  5. backend_new/echantillons/views.py - Django checks role and saves with collector.
  6. backend_new/echantillons/serializers.py - Django validates fields and returns JSON.
