# Evaluation Divergence Detection — Design Spec

**Backlog items:** 16/3 + 10/6 (Cross-panel evaluation supervision)
**Status:** Design

---

## Goal

When the Panel Supervisor consults a sample's cross-panel view, the system flags any taster whose evaluation deviates significantly from the rest of the panel — automatically.

This is the project's **main AI showpiece**: a complete ML pipeline (data generation → cleaning → training → evaluation → deployment → integration) demonstrating real ML work, not API calls.

---

## Approach

**Algorithm:** Isolation Forest (unsupervised anomaly detection from `scikit-learn`)

Why Isolation Forest:
- No labels required (no need for "ground truth divergent" data from real users)
- Handles multi-dimensional features (multiple sensory attributes per evaluation)
- Fast training, fast inference
- Well-known, well-supported, easy to defend in jury Q&A

---

## Phase 1 — Python Notebook (`ml_service/notebooks/divergence_training.ipynb`)

The notebook is the **proof-of-work artifact** for the jury.

### Step 1 — Synthetic data generation
Generate ~500 evaluations with:
- `taster_id`, `sample_id`, `session_id`
- Sensory scores (0–10 each):
  - `fruite` (fruity)
  - `amer` (bitter)
  - `piquant` (pungent)
  - `defauts_intensite` (defect intensity)
- `classification` (Extra Vierge / Vierge / Lampante)
- `is_divergent` — ground truth label, ~15% of rows generated as outliers

Outliers generated by injecting deliberately deviant scores relative to their session's panel average.

### Step 2 — Exploratory analysis
- Score distributions (histograms)
- Correlation matrix between attributes
- Boxplots per session

### Step 3 — Data cleaning
- Drop rows with all-null sensory scores
- Impute single missing values with panel median for that sample
- Remove impossible values (>10 or <0)
- Encode classification as ordinal (0=Lampante, 1=Vierge, 2=Extra Vierge)
- Normalize scores to [0,1]

### Step 4 — Feature engineering
For each evaluation, compute deviation features against the panel average for the same sample:
- `delta_fruite = score_fruite - panel_avg_fruite`
- `delta_amer = ...`
- `delta_piquant = ...`
- `delta_defauts = ...`
- `delta_classification = ...`

The model trains on these **deltas**, not raw scores. This is the critical design decision — divergence is relative, not absolute.

### Step 5 — Train Isolation Forest
```python
from sklearn.ensemble import IsolationForest
model = IsolationForest(contamination=0.15, random_state=42)
model.fit(X_train)
```

### Step 6 — Evaluate
- Confusion matrix vs ground-truth `is_divergent`
- Precision, recall, F1
- ROC curve
- Visualize: 2D PCA projection with flagged points highlighted

### Step 7 — Export
```python
import joblib
joblib.dump(model, "divergence_model.pkl")
```

## Phase 2 — Flask Endpoint

Lives in the same `ml_service/` as the lab OCR service.

```
POST /ai/detect-divergence
Content-Type: application/json

body: {
  "sample_id": "uuid",
  "evaluations": [
    {
      "taster_id": "uuid",
      "fruite": 7.0,
      "amer": 5.5,
      "piquant": 6.0,
      "defauts_intensite": 0.0,
      "classification": "extra_vierge"
    },
    ...
  ]
}

Response 200:
{
  "results": [
    {
      "taster_id": "uuid",
      "status": "normal",
      "anomaly_score": -0.05
    },
    {
      "taster_id": "uuid",
      "status": "divergent",
      "anomaly_score": 0.42,
      "main_deviations": ["amer", "defauts_intensite"]
    }
  ]
}
```

`main_deviations` = top 2 attributes with largest absolute delta from panel average. This gives the supervisor a hint at *why* it's flagged.

## Phase 3 — Flutter Integration

### Service: `DivergenceDetectionService` (lib/5_chef_degustateur/.../services/)
- `Future<List<DivergenceResult>> detect(String sampleId, List<Evaluation> evaluations)`

### UI integration
On the existing **Cross-panel evaluation supervision** page (16/2):
- After loading evaluations, automatically call divergence detection
- Each panel member's card shows a status badge:
  - Vert "Normal" if `status == normal`
  - Rouge "⚠ Divergence" if `status == divergent`
- Divergent cards expand to show: "Diverge principalement sur: amer, défauts"
- Supervisor can confirm or dismiss the flag (feedback loop for future retraining — out of scope for now)

## Architecture

```
Flutter app
    │
    ├─ Django REST (samples, evaluations, auth, etc.)
    │       ↕
    │   PostgreSQL
    │
    └─ Flask ML service
            │
            ├─ /ocr/lab-report  → Tesseract pipeline
            └─ /ai/detect-divergence → Isolation Forest model

```

Both endpoints share preprocessing utilities, logging, and config.
