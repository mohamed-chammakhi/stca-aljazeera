Simple project flow

How login travels through your project

This page follows one action: the user types an email and password, presses Log In, and the app opens the correct dashboard. The goal is not to read every line. The goal is to know where the action goes next.

The easiest way to understand authentication: the login page does not decide if the user is real.
The page sends the email and password to a service. The service asks the API client. The API client asks Django. Django returns tokens. Then Flutter asks who the user is and opens the correct page using the role.

The login flow, slowly

1

The user presses Log In

Start here. This is the login screen. The page takes the text from the email and password fields, then calls authService.login().

File to open

lib/main.dart

Look around lines 139 to 153.

The important code

final user = await authService.login(
  email: emailController.text.trim(),
  password: passwordController.text,
);
In simple words: "Take what the user typed and ask the authentication service to log them in."
2

AuthService organizes the login

AuthService is small, but very important. It does two things: first it asks the API client to login, then it asks who the connected user is.

File to open

lib/core/services/auth_service.dart

Look at lines 7 to 18.

The important code

Future<UserProfile> login({
  required String email,
  required String password,
}) async {
  await apiClient.login(email, password);
  return currentUser();
}
In simple words: "First get the tokens. Then use those tokens to get the user profile."
3

ApiClient sends email and password to Django

This is the first real trip to the backend. Flutter sends the email and password as JSON. Django checks them.

File to open

lib/core/api_client.dart

Look at lines 287 to 300.

The important code

final response = await http.post(
  _uri('/api/auth/login/'),
  headers: {'Content-Type': 'application/json'},
  body: jsonEncode({
    'email': email,
    'password': password,
  }),
);
Flutter has Dart values email = "collecteur@test.com" password = "Test123!"
ApiClient sends JSON body { "email": "collecteur@test.com", "password": "Test123!" }
Django returns Tokens { "access": "...", "refresh": "..." }
4

ApiClient saves the tokens

The tokens are like proof that the user is logged in. Flutter saves them in secure storage so future requests can use them.

File to open

lib/core/api_client.dart

Still around lines 294 to 300.

The important code

final data = jsonDecode(response.body);

await saveTokens(
  access: data['access'] as String,
  refresh: data['refresh'] as String,
);
In simple words: "Login worked, so store the access token and refresh token safely on the device."
5

AuthService asks for the current user

The tokens only prove the user is connected. They do not tell the screen which dashboard to open. So Flutter asks Django for the current user's profile.

File to open

lib/core/services/auth_service.dart

Look at lines 15 to 18.

The important code

Future<UserProfile> currentUser() async {
  final data = await apiClient.get('/api/users/me/');
  return UserProfile.fromJson(data);
}
In simple words: "Now that we are logged in, ask Django: who is this user?"
6

ApiClient adds the token to the profile request

The profile endpoint is protected. Flutter must send the access token in the request header.

File to open

lib/core/api_client.dart

Look at lines 93 to 98, then 196 to 200.

The important code

return {
  'Content-Type': 'application/json',
  if (token != null)
    'Authorization': 'Bearer $token',
};
Request Endpoint GET /api/users/me/
Header Proof of login Authorization: Bearer access_token
Response User profile { "email": "...", "role": "collecteur", "nom": "Ben Ali" }
7

The JSON profile becomes a UserProfile object

Django sends JSON. Flutter prefers Dart objects. The model translates the JSON profile into a UserProfile.

File to open

lib/core/models/user_profile.dart

Look at lines 45 to 56.

The important code

factory UserProfile.fromJson(Map<String, dynamic> json)
  => UserProfile(
    email: json['email'] as String,
    role: RoleUtilisateurX.fromJson(
      json['role'] as String,
    ),
    nom: json['nom'] as String,
    prenom: json['prenom'] as String,
  );
The most important field here is role. Without it, Flutter would not know which page to open.
8

The role string becomes a Flutter role

Django sends role as text, for example "collecteur". Flutter converts that text into a role value it can use in a switch.

File to open

lib/core/models/enums.dart

Look at lines 37 to 44.

The important code

static RoleUtilisateur fromJson(String s) {
  switch (s) {
    case 'collecteur':
      return RoleUtilisateur.collecteur;
    case 'chef_panel':
      return RoleUtilisateur.chefPanel;
  }
}
In simple words: Django says "collecteur"; Flutter understands RoleUtilisateur.collecteur.
9

Flutter opens the correct dashboard

Now the login page has a full user object, including the role. It uses that role to pick the correct first screen.

File to open

lib/main.dart

Look at lines 39 to 46, then 155 to 176.

The important code

final role = user.role;
final destination = _destinationForRole(role);

Navigator.pushReplacement(
  context,
  PageRouteBuilder(
    pageBuilder: (...) => destination,
  ),
);
If role is collecteur
Flutter opens MesEchantillonsPage()
Meaning The collector arrives directly in their sample management screen.

What happens when the app opens again?

A

AuthGate tries to restore the session

When the app starts, it does not immediately show the login page. It first checks if a saved token can still identify the user.

File to open

lib/main.dart

Look at lines 49 to 80.

The important code

Future<void> _restoreSession() async {
  try {
    final user = await authService.currentUser();
    Navigator.pushReplacement(
      context,
      MaterialPageRoute(
        builder: (_) => _destinationForRole(user.role),
      ),
    );
  } catch (_) {
    setState(() => _checkingSession = false);
  }
}
If `/api/users/me/` works, the app opens the dashboard. If it fails, the app shows the login page.

What happens when the token expires?

B

ApiClient silently refreshes the access token

If Django says the access token is expired, the API client uses the refresh token to get a new access token, then retries the request.

File to open

lib/core/api_client.dart

Look at lines 120 to 157.

The important code

if (response.statusCode == 401) {
  final refreshed = await _refreshAccessToken();
  if (refreshed) response = await request();
}
In simple words: "If the badge expired, get a new badge and try again."

What happens during logout?

C

ApiClient tells Django and deletes local tokens

Logout has two sides: tell Django to invalidate the refresh token, then remove the saved tokens from the phone.

File to open

lib/core/api_client.dart

Look at lines 303 to 316.

The important code

await http.post(
  _uri('/api/auth/logout/'),
  headers: headers,
  body: jsonEncode({'refresh': refresh}),
);

await clearTokens();

The architecture in one sentence

For authentication, your project works like this:

LoginPage collects email and password, AuthService organizes the login, ApiClient talks to Django and stores JWT tokens, Django returns the user profile, UserProfile reads the role, and main.dart opens the correct role page.

Files you should open, in this exact order

  1. lib/main.dart - login button, session restore, and role redirection.
  2. lib/core/services/auth_service.dart - connects login, current user, and logout.
  3. lib/core/api_client.dart - sends login request, stores tokens, adds Bearer token, refreshes token, logs out.
  4. lib/core/models/user_profile.dart - converts Django user JSON into a Dart user object.
  5. lib/core/models/enums.dart - converts role text like collecteur into a Flutter role.
